01 / typography as machinery

This picture is one letter.

A maze to your eyes. A single character to the extractor. Walk from blue to red, then try copying the drawing.

Open the PDFOpen its other readingDirect-drawing control
Reveal the trick

The maze is drawn inside a Type 3 font's /CharProcs stream. The page invokes that glyph once. Change only its Unicode mapping and the maze says LOST, while looking exactly the same.

Measured here: pixel-identical original, alternate and direct-drawing control in MuPDF and Poppler. Extraction differs. Selection behaviour in interactive viewers is not yet measured.

Enter backstage and press Enter on the page. Step, Run and Reset reveal a toy machine with eight memory cells. It uses PDF form JavaScript, with no external requests.

The state-machine logic and PDF field structure pass automated checks. Live viewer interaction and save/reopen persistence are not tested. A viewer that ignores scripts will retain the static instruction sheet.

03 / reader improvisation

What did the reader repair?

Three single-purpose mutations. Same baseline, different structural damage.

BaselineWrong xref offsetWrong stream lengthTruncated update
Measured results

Both extractors accepted all three specimens and returned the baseline text. MuPDF reported repair for the xref mutation and a length warning for the stream mutation. Poppler's text extractor returned no diagnostics. Neither reported an error for the truncated appended update.

These are diagnostic differences, not demonstrated visual divergence, crashes or security vulnerabilities. Repair internals beyond the diagnostics remain unknown.
