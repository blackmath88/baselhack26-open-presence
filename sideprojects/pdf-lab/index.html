07 / A LOGIC CIRCUIT DISGUISED AS LAYERS
The lock is the layers panel.
Three switches. No scripts. The intended combination is A on, B off, C on. Does every reader agree?
Open saved state 000 ↗Inspect observationsRead the experiment cards







How to reverse-engineer the lock
Find /OCProperties in the catalog. A, B and C are optional-content groups. The gate is a membership dictionary with /VE [/And 5 0 R [/Not 6 0 R] 7 0 R]. The page uses marked content to associate paint with that dictionary.
All eight PDFs have identical page streams. Only the catalog's initial layer states differ. Poppler and PDFium match the intended table in all states. This MuPDF build keeps the gate visible and differs on AllOn and AnyOff. The cause remains unassigned; this is not a claim about every MuPDF release.
Try the PDF's actual layers panel in your reader and record its version. These saved-state images do not establish interactive support in Acrobat, Preview or browser viewers.


08 / DATA PRIMITIVES BECOME COMPUTATION
Pictures that add.
Paint the two inputs. Every pixel becomes a one-bit half-adder. Follow the intermediate pictures: the whole circuit uses NAND.
This is a live Boolean simulator in the workbench. The accompanying PDF explains the circuit; it does not execute it. It is not a JBIG2 decoder or a reproduction of FORCEDENTRY.




Input A


Input B


N = NAND(A, B)


L = NAND(A, N)


R = NAND(B, N)


Sum = NAND(L, R)


Carry = NAND(N, N)


Open the circuit sheet ↗Read the five-gate network
What this does—and what it teaches
A black-and-white picture is a grid of bits. Boolean combination operations can implement logic independently at each position. The carry output is a separate picture: this is not yet a multi-bit adder with carry propagation.
The historical JBIG2 exploit needed an implementation vulnerability. Our simulator has no codec inputs, vulnerable parser or exploit chain. The shared idea is the surprising computational power of seemingly simple data operations.



09 / A LANGUAGE INSIDE THE PAINT
The colour
is a program.
This pattern is computed by a tiny stack program stored in the PDF. A Type 4 calculator function takes a position and returns a colour. No JavaScript, no embedded pixel grid.
Open the artwork ↗Follow the calculation
Read the painting's program
{ 1440 mul cos exch 2160 mul sin mul
  1 add 2 div dup 1 exch sub 0.35 }
Inputs: x and y. Output: RGB. The waves are v=(sin(2160x)×cos(1440y)+1)/2; colour is (v, 1−v, 0.35). Angles are degrees.
All three tested engines render the pattern. Six interior samples per engine agree with the analytic formula within 0.022 per colour channel. This is a sampling check, not whole-image equality.
Change the frequencies in weird.py, rebuild, then see how sampling affects the result.
