# Working cabinet 001
31 October 2026. Eight generated PDFs, a local gallery, deterministic generator and bounded evidence runner.

## Run
From this folder:

```sh
python3 build.py
python3 -m http.server 8080 --bind 127.0.0.1
```

Open http://127.0.0.1:8080. Generation uses only Python's standard library. PDFs are deliberately ASCII and uncompressed for inspection. No external assets or API credentials.

Verification environment used: Python 3.12.14, PyMuPDF 1.26.6, pypdf 6.10.0, Poppler 24.02.0; Node runs the isolated toy-machine test. Install the two Python packages from `requirements-check.txt` and obtain Poppler through your platform's package manager, then:

```sh
python3 check.py
node test-machine.js
```

`check.py` is Linux/POSIX-oriented and sets per-child CPU, address-space, file-output and wall-time limits. The fixtures are tiny owned files; this is not an arbitrary-upload service or a security sandbox. No PDF JavaScript is executed by these checks. Use offline disposable viewer environments for active testing. Results contain full commands implicitly defined in check.py, tool versions, hashes, stdout and stderr. PNG previews are local intermediates, regenerated by check.py.

## B01: observed
The illustration is a seeded 18-by-18 perfect maze drawn by one Type 3 glyph. The original maps to A, its alternate maps to LOST. Both and the direct-drawing control have identical pixels in MuPDF and Poppler at the tested settings. The PDF also contains ordinary title/caption text: the claim of one letter concerns the maze only. Structural assertions verify the Type 3 dictionary and one CharProc. Both pages were visually reviewed.

## B02: implemented, viewer qualification pending
An AcroForm with canonical fields, explicit appearances and field-action JavaScript. Enter `backstage` and press the Enter button to reveal a toy machine. Step alternates LOAD/ADD and DRAW operations; Run is bounded; Reset clears it. The toy program populates eight cells. It is intentionally discoverable in source and is not a security gate.

Verified: field tree and widget correspondence, appearance streams, locked state rendering; JavaScript logic tested in Node with a mock document API. Not verified: live Acrobat/PDFium/PDF.js interaction, UI event integration, persistence or reopened state. Do not call this exhibit viewer-qualified until those observations are recorded. The machine exposes numeric memory rather than a graphical pixel display in this first implementation.

## B03: observed negative result with diagnostic differences
All mutated specimens were accepted by both text extractors and yielded baseline text. MuPDF exposed xref repair and a stream-length warning; Poppler emitted no text-extraction diagnostics. The truncated appended update was accepted without warnings. This does not establish that both parsers use the same recovery algorithm. It is not evidence of a crash, visual divergence or trust-boundary crossing.

Stream-length and startxref substitutions preserve byte widths so offsets are not accidentally changed. The truncated-update specimen appends a replacement catalog and cuts its new trailer. Tests currently cover extraction; a minimized divergent-rendering case has not been found or claimed.
